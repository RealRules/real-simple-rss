# Real Simple RSS

A lightweight, self-hosted, multi-user RSS and Atom reader that runs out of a
single directory. Plain PHP 8.4+ on MySQL/MariaDB — no framework, no build
step, and no Composer packages needed at runtime.

## Features

- **Single-directory deployment** — upload the files and run the setup wizard.
- **Multi-user** — each user manages their own feeds; an admin panel handles
  user creation, editing and deletion.
- **Three-pane reader UI** — feed sidebar, post list and article pane, with
  resizable columns and a responsive single-column layout on small screens.
- **Feed sections** — the sidebar groups feeds into Unread, Read, Inactive
  (no posts in over a year) and Empty sections.
- **Infinite scroll** — older articles load automatically as you scroll.
- **Auto-mark read** — opening a post marks it read in the background; if the
  database write fails, the change is rolled back and an error is shown.
- **OPML import/export** for subscriptions.
- **Background refresh** via cron (CLI or a secret web URL), with protection
  against overlapping runs and optional purging of old read posts.

## Requirements

| | |
|---|---|
| PHP | 8.4 or newer |
| PHP extensions | `pdo`, `pdo_mysql`, `curl`, `dom`, `simplexml`, `mbstring` |
| Database | MySQL or MariaDB |
| Web server | Apache (`.htaccess` support) or Nginx (config below) |

## Installation

### 1. Upload the files

Copy the repository contents to a directory on your web server, for example
`/var/www/html/rss/`. The directory must be writable by PHP during setup:
the wizard writes `config.php` and `install.lock`, and the application keeps
its session files in a `sessions/` subdirectory.

### 2. Run the setup wizard

Open the location in your browser (`https://your-site.example/rss/`). You are
redirected to `setup.php`, which asks for:

- database host, port, name, user and password
- an application name (shown in the UI; defaults to "Real Simple RSS")
- an administrator username, email and password

The wizard creates the tables, writes `config.php` (including a generated
cron secret) and locks itself with `install.lock`.

### 3. Lock things down

- **Delete `setup.php`** from the server. It refuses to run once installed,
  but removing it entirely is the safer option.
- **Reduce the database account's privileges.** Installation needs `CREATE`;
  day-to-day operation only needs data privileges:

  ```sql
  REVOKE ALL PRIVILEGES ON `real_simple_rss`.* FROM 'rsrss_user'@'localhost';
  GRANT SELECT, INSERT, UPDATE, DELETE ON `real_simple_rss`.* TO 'rsrss_user'@'localhost';
  FLUSH PRIVILEGES;
  ```

  Adjust the database name, user and host to match your installation.

### 4. Set up the cron job

Feeds refresh in the background via `cron.php`. Use either:

**A system crontab** (recommended):

```
* * * * * php /path/to/rss/cron.php
```

**A web cron** — call the secret URL shown in the admin panel
(Admin panel → Synchronization). The token is masked until you choose
to reveal it:

```
https://your-site.example/rss/cron.php?token=YOUR_CRON_SECRET
```

Overlapping runs are prevented by a database lock and web-triggered runs are
throttled. The admin panel also holds the retention setting, which purges
read posts older than a given number of days (0 = never).

## Nginx configuration

The bundled `.htaccess` only applies to Apache (with `AllowOverride All`).
On Nginx, add the equivalent rules — and keep them **before** the `\.php$`
location, since the first matching regex wins:

```nginx
server {
    # ... your server config ...

    autoindex off;

    # Deny the session store and any version-control path.
    location ~ ^/sessions { return 404; }
    location ~ /\.git { return 404; }

    # Deny sensitive files (equivalent of the bundled .htaccess).
    location ~ ^/(config\.php|config\.sample\.php|schema\.sql|install\.lock|composer\.(json|lock)|\.gitignore|\.htaccess|\.htpasswd)$ {
        return 404;
    }

    # PHP via FastCGI - adjust the socket to your setup.
    location ~ \.php$ {
        include fastcgi_params;
        fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
        fastcgi_pass unix:/run/php/php8.4-fpm.sock;
    }
}
```

The paths above assume the app is served from the root of the server block;
prefix them (for example `^/rss/sessions`) when running from a subdirectory.

## Configuration

`config.php` is generated by the installer; `config.sample.php` documents all
options.

| Key | Default | Purpose |
|---|---|---|
| `app_name` | `Real Simple RSS` | Name shown in the UI and OPML export |
| `db_host`, `db_port`, `db_name`, `db_user`, `db_pass` | — | Database connection |
| `cron_secret` | generated | Token required for web-triggered cron runs |
| `allow_private_hosts` | `false` | Allow feeds hosted on private/loopback addresses (disables part of the SSRF protection) |
| `allowed_feed_ports` | `[80, 443]` | Ports feed URLs may connect to |
| `trusted_proxies` | `[]` | Proxy IPs whose `X-Forwarded-Proto` header may be trusted |

## Security notes

- Serve over HTTPS: this enables the secure cookie flag and HSTS.
- Feed fetching blocks private, loopback and non-routable addresses by
  default, restricts the ports it may connect to, validates and pins every
  redirect hop, and caps response sizes.
- External feed HTML is sanitized server-side (tag/attribute whitelist)
  before it reaches the browser.
- All state-changing API calls require POST with a CSRF token; sessions are
  HttpOnly, SameSite=Lax, with a one-year lifetime.
- Failed logins are throttled per account and per IP address.
- The web cron URL is masked in the interface and revealed only on demand.
- `config.php`, `install.lock`, `sessions/` and `vendor/` are gitignored and
  blocked from web access.

## Updating

Keep `config.php` and the `sessions/` directory, replace everything else.
The installer stays locked via `install.lock` and does not need to run again.

## Development

`composer.json` declares the PHP 8.4+ platform requirements; there are no
runtime packages. `AGENTS.md` contains the technical specification the
codebase follows.

The test suite covers the pure library functions — feed parsing, URL
resolution, HTML sanitization, IP screening — and needs no database or
network:

```
php tests/run.php      # or: composer test
```

The `tests/` directory is development-only and does not need to be deployed.
